# Go Goroutine: Deep Dive

## Горутина (Goroutine) — это легковесный поток управления, управляемый Go Runtime, а не операционной системой

```go
go doWork() // Запуск функции в отдельной горутине
```

Когда пишешь go doWork(), Go не создает тяжелый поток в Windows/Linux.
Он создает маленькую внутреннюю структуру в памяти и отдаёт её своему планировщику.

| Характеристика                |        Поток ОС (OS Thread)         |              Горутина (Goroutine)               |
| :---------------------------- | :---------------------------------: | :---------------------------------------------: |
| Кем управляется               |     Ядром операционной системы      |          Go Runtime (планировщиком Go)          |
| Размер памяти                 |       ~1-2 МБ (фиксированный)       |             ~2 КБ (растущий стек!)              |
| Переключение (Context Switch) | Дорогое (сохранение регистров ядра) | Очень дешевое (в пользовательском пространстве) |
| Параллелизм (CPU)             |        Да (на разных ядрах)         |             Да (на всех ядрах CPU)              |

💡 **Ключевой вывод**: Поскольку горутина весит всего ~2 КБ, ты можешь легко запустить 100 000 горутин на обычном ноутбуке, и программа не упадет по память (Out of Memory). Если запустить 100 000 системных потоков в C++/Java — ОС мгновенно «умрет».

### Динамический стек: Как Go экономит память?

-   В языках вроде C++ или Java каждому потоку выделяется фиксированный кусок памяти (например, 1 или 2 МБ) под стек вызовов функций.

-   В Go при создании горутины ей выделяется крошечный стек размерностью всего 2 КБ.

-   Если функция внутри горутины делает много глубоких вызовов или рекурсию, Go автоматически увеличивает (растит) стек в куче, перенося данные. Когда вызовы завершаются — стек уменьшается.

### Главная опасность: Функция main и завершение программы

В JS цикл событий работает, пока есть активные таски/таймеры.
В Go главная горутина (функция main) — главнее всех. Если main() завершила работу, всё приложение мгновенно умирает, даже если 1000 фоновых горутин еще работали!

```go
package main

import (
    "fmt"
    "time"
)

func main() {
    go func() {
        time.Sleep(1 * time.Second)
        fmt.Println("Привет из горутины!")
    }()

    fmt.Println("Главная функция завершена")
    // Программа завершается МГНОВЕННО!
    // "Привет из горутины!" НИКОГДА НЕ НАПЕЧАТАЕТСЯ!
}
```

Чтобы дождаться выполнения горутин, в Go используют синхронизаторы (например, sync.WaitGroup).

## Модель G-M-P (с Go 1.1+)

| Буква         | Что это              | Роль                                            |
| :------------ | :------------------- | :---------------------------------------------- |
| G (Goroutine) | Сама горутина        | Структура с стеком, указателем на код, статусом |
| M (Machine)   | Поток ОС             | Реально выполняет код на CPU                    |
| P (Processor) | Логический процессор | Контекст планирования, очередь горутин          |

Связь:

```text
G должен выполняться на M, но только если у M есть P.
Количество P ≈ GOMAXPROCS (по умолчанию = число ядер CPU).
```
