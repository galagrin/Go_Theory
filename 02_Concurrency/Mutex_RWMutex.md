# sync.Mutex & sync.RWMutex: Взаимное исключение

`Mutex` (Mutual Exclusion) используется для защиты критических секций — участков кода, где несколько горутин обращаются к общей памяти, и хотя бы одна из них делает запись (для предотвращения Data Race).

---

## 1. sync.Mutex (Классический мьютекс)

Предоставляет монопольный доступ к ресурсу. В каждый момент времени только **одна** горутина может удерживать блокировку.

```go
type SafeCounter struct {
    mu    sync.Mutex
    value int
}

func (c *SafeCounter) Inc() {
    c.mu.Lock()
    defer c.mu.Unlock() // Всегда освобождаем через defer!
    c.value++
}
```

### Основные правила:

-   Lock(): Захватывает мьютекс.

    Если он уже занят другой горутиной, вызывающая горутина блокируется (засыпает) до его освобождения.

-   Unlock(): Освобождает мьютекс. Вызов Unlock() на незаблокированном мьютексе вызывает Panic!.

-   Передача: Мьютекс нельзя копировать после первого использования (передавать только по указателю \*sync.Mutex или внутри структуры по указателю).

## 2. sync.RWMutex (Мьютекс чтения/записи)

Оптимизирован для сценариев Read-Heavy (когда читают часто, а пишут редко). Позволяет параллельно читать нескольким горутинам.

| Метод               | Что делает       | Кто может выполнять параллельно                |
| ------------------- | ---------------- | ---------------------------------------------- |
| RLock() / RUnlock() | Захват на чтение | Множество горутин-читателей одновременно       |
| Lock() / Unlock()   | Захват на запись | Строго 1 горутина-писатель (все читатели ждут) |

```go
type Cache struct {
    mu    sync.RWMutex
    items map[string]string
}

// Параллельные вызовы Get не блокируют друг друга!
func (c *Cache) Get(key string) string {
    c.mu.RLock()
    defer c.mu.RUnlock()
    return c.items[key]
}

func (c *Cache) Set(key, val string) {
    c.mu.Lock()
    defer c.mu.Unlock()
    c.items[key] = val
}
```

## ⚠️ Подводные камни (Edge Cases):

1. Защита от Starvation (Голодания писателей):

    Если писатель вызовет Lock(), новые читатели с RLock() станут в очередь за ним и не смогут проскочить вперед, пока писатель не закончит.

2. Reentrancy (Рекурсивный вызов):

    В Go мьютексы нереэнтрабельны. Если горутина вызовет Lock() дважды подряд сама на себе, она упадет в Deadlock сама с собой.
