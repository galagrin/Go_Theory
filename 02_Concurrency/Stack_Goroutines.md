# Планировщик: до Go 1.14 и после

До Go 1.14 - кооперативная многозадачность
Горутина сама должна была отдать управление. Точки, где она могла быть переключена:

-   вызов функции
-   операции с каналами
-   системные вызовы
-   runtime.Gosched()

```go
go func() {
    for {
        // плотный цикл без вызовов функций
        // эта горутина могла навсегда захватить поток ОС
    }
}()
```

Такая горутина блокировала целый поток (M), и если таких было много — программа могла «встать».

Go 1.14+ — асинхронная вытесняющая многозадачность (asynchronous preemption)
Начиная с Go 1.14 runtime может насильно остановить горутину.
Как это работает (упрощённо):

На Unix-системах используется сигнал (SIGURG)
Runtime периодически проверяет, долго ли горутина работает
Если слишком долго — посылает сигнал и заставляет её остановиться в безопасной точке

Теперь даже бесконечный цикл без вызовов функций почти всегда можно вытеснить.

**Важно**: это не делает горутины вытесняемыми на 100% как потоки ОС, но значительно лучше, чем было.

## Стек горутины: как он растёт

| Период   | Подход                              | Проблема                                                                                       |
| :------- | :---------------------------------- | :--------------------------------------------------------------------------------------------- |
| Early Go | Segmented stacks (разделённый стек) | "«Hot split» — постоянные проверки и переключения между сегментами, потери производительности" |
| Go 1.4+  | Contiguous stacks (сплошной стек)   | "Стек копируется в новый, больший кусок памяти при росте"                                      |

### Как растёт стек сейчас

1. При создании горутины выделяется маленький стек (обычно 2 КБ или 4 КБ, зависит от версии и архитектуры).
2. Перед каждым вызовом функции runtime проверяет: «хватит ли места?».
3. Если нет — происходит stack growth:
    - выделяется новый стек большего размера (обычно ×2)
    - все данные со старого стека копируются в новый
    - указатели внутрь стека обновляются (это сложно и делается runtime)
    - старый стек освобождается

Стек также может уменьшаться, если долго используется мало места (при сборке мусора / определённых условиях).

Поэтому ты можешь спокойно делать умеренную рекурсию — стек вырастет. Но бесконечная рекурсия всё равно уронит программу (по памяти или по лимиту).
