# sync.Cond & sync.Pool

## 1. sync.Cond (Условные переменные)

`sync.Cond` используется для оповещения горутин о наступлении определенного события/условия.

-   **`Wait()`:** Блокирует горутину и освобождает связанный мьютекс, пока не придет сигнал.
-   **`Signal()`:** Пробуждает **одну** ожидающую горутину.
-   **`Broadcast()`:** Пробуждает **все** ожидающие горутины.

> **На практике:** В современном Go `sync.Cond` используется редко, так как в 95% случаев его удобнее и идиоматичнее заменить **каналами (`chan struct{}`)**.

## 2. sync.Pool (Пул повторно используемых объектов)

`sync.Pool` — это временный буфер для хранения и повторного использования выделенной памяти (для уменьшения нагрузки на **Garbage Collector**).

Используется для буферов байт (`bytes.Buffer`), JSON-декодеров или тяжелых объектов.

```go
var bufPool = sync.Pool{
    New: func() any {
        // Вызывается, если пул пуст
        return new(bytes.Buffer)
    },
}

func Process() {
    // 1. Берем объект из пула
    buf := bufPool.Get().(*bytes.Buffer)
    buf.Reset() // Очищаем состояние!

    defer bufPool.Put(buf) // 3. Возвращаем обратно в пул

    // 2. Используем buf...
    buf.WriteString("hello")
}
```

## ⚠️ Критическое правило sync.Pool:

Все объекты из sync.Pool автоматически очищаются Garbage Collector'ом при каждом запуске GC.

Пул нельзя использовать как кеш данных (например, БД-сессий), он предназначен только для временных буферов памяти!
