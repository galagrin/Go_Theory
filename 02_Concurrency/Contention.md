# Состязание мьютексов (lock contention)

Состязание мьютексов (lock contention) в Go возникает, когда несколько горутин одновременно пытаются захватить один и тот же примитив синхронизации (sync.Mutex или sync.RWMutex), из-за чего часть из них блокируется и теряет производительность.

Для поиска таких проблем используют встроенный инструмент Go pprof.

## Как найти и измерить contention в Go

Включение профиля:

-   По умолчанию сбор данных о блокировках мьютексов отключен. Задайте долю сэмплирования в коде (например, 1 — для записи каждого события):

```
runtime.SetMutexProfileFraction(1)
```

HTTP-эндпоинт:

-   Импортируйте пакет \_ "net/http/pprof", чтобы просматривать или скачивать готовый профиль по адресу http://localhost:8088/debug/pprof/mutex.

Анализ через CLI:

-   Запустите интерактивную консоль анализа командой: go tool pprof http://localhost:8088/debug/pprof/mutex.

Интерпретация: Используйте команду top или визуализацию графа (svg/web), чтобы найти строчки кода, на которых горутины дольше всего ждут освобождения лока.

## Как исправить lock contention

Уменьшение критической секции:

-   Сокращайте код внутри блока mu.Lock() и mu.Unlock(), убирая оттуда тяжелые вычисления, логику или сетевые запросы.

Шардирование (Sharding):

-   Разбейте один глобальный мьютекс и защищаемый им ресурс (например, общую карту map) на несколько независимых частей по хэшу ключа.

Альтернативные структуры:

-   Применяйте каналы для передачи данных вместо блокировок или используйте sync.Map для консистентного чтения/записи без жестких единых локов.
