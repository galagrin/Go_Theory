# Go 1.22: изменение семантики переменных цикла (Loop Variable Capture)

## Проблема (до Go 1.22)

До Go 1.22 переменные, объявленные в `for`, создавались **один раз** и переиспользовались на всех итерациях.

```go
digits := []int{1, 2, 3, 4, 5}

for _, d := range digits {
    go func() {
        fmt.Println(d) // все горутины замыкаются на одну и ту же d
    }()
}
```

### Что происходило

-   Цикл очень быстро пробегал значения 1 → 2 → 3 → 4 → 5.
-   К моменту реального выполнения горутин цикл уже завершался.
-   Переменная d содержала последнее значение — 5.
-   Все горутины читали одну и ту же переменную → в выводе почти всегда было:

```
5
5
5
5
5
```

> Это классическая ошибка loop variable capture.

---

### Решение в Go 1.22+

---

Начиная с Go 1.22 каждая итерация цикла получает свою собственную переменную.

```go
for _, d := range digits { // на каждой итерации создаётся новая d
    go func() {
        fmt.Println(d) // горутина захватывает d именно этой итерации
    }()
}
```

Теперь каждая горутина получает своё значение (1, 2, 3, 4 или 5).

> Порядок вывода по-прежнему не гарантирован — горутины выполняются конкурентно.

Изменилось только то, что печатаются правильные значения, а не одни пятёрки.

## Как писать совместимо со старыми версиями

### Способ 1: Передача параметра (рекомендуется)

```go
for _, d := range digits {
    go func(d int) { // создаётся копия
       fmt.Println(d)
    }(d)
}
```

### Способ 2: Локальная переменная внутри цикла

```go
for _, d := range digits {
    d := d // новая переменная в этой итерации
    go func() {
        fmt.Println(d)
    }()
}
```

## Важные замечания

Изменение касается всех переменных, объявленных в for (i, v в range и т.д.).

Это breaking change в семантике языка, но сделано намеренно и с хорошей обратной совместимостью на практике.

Даже после исправления для ожидания горутин лучше использовать sync.WaitGroup, а не time.Sleep.
